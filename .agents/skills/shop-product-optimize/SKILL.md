# 产品优化：知识库优先

## 首先定位并读取项目知识库

收到商品优化请求后，先做本地知识检索，再决定是否需要最新后台数据或外部规则。不要只凭通用电商经验直接改文案或开浏览器。

以用户指定项目或当前仓库为准，定位含 `知识库/经营规则.json` 和 `知识库/分析方法.md` 的目录。当前工作区是仓库父目录时检查 `shop_test/`。本技能随仓库放在 `.agents/skills/shop-product-optimize/`，可沿技能文件真实路径向上三级定位仓库；通过个人技能目录的软链接调用时先解析真实路径。不要硬编码本机用户名，也不要把其他项目的知识库套到当前项目。

开始时读取以下小文件；后续仅按问题读取相关资料：

- [知识库首页](../../../知识库/README.md)：现有资料的入口。
- [经营规则](../../../知识库/经营规则.json)：用户确认的成本、材质、供应事实、偏好与权限。
- [分析方法](../../../知识库/分析方法.md)：数据日期、利润口径、执行与复盘约定。

用户未指定平台时，结合当前聊天、商品ID和项目最近记录判断。当前话题明确是Joom时沿用Joom；仍无法区分时先完成公共知识检索，再只询问影响下一步的平台或商品范围。

## 按平台与问题检索

### Joom

先读 [平台规则入口](../../../知识库/平台规则/Joom/README.md) 和 [优化检查清单](../../../知识库/平台规则/Joom/优化检查清单.md)。按实际问题选择，避免每次加载全部知识库：

| 问题 | 资料 |
| --- | --- |
| 标题、描述、图片、材质、尺码、变型、审核 | [商品与内容规则](../../../知识库/平台规则/Joom/商品与内容规则.md) |
| 人物/球队印花、侵权、欧盟限售、标签与定制 | [合规与侵权规则](../../../知识库/平台规则/Joom/合规与侵权规则.md) |
| 价格、折扣、广告预算/竞价、POGS与ACOS | [广告与定价规则](../../../知识库/平台规则/Joom/广告与定价规则.md) |
| 发货、取消、退款、店铺健康 | [履约与店铺表现](../../../知识库/平台规则/Joom/履约与店铺表现.md) |
| 追查官方原文、适用范围和核查日期 | [来源索引](../../../知识库/平台规则/Joom/来源索引.json) |

### 美客多、速卖通及其他平台

先用 `rg --files 知识库` 查相关资料；按平台、站点、商品ID或问题关键词缩小范围。速卖通印花、品牌或侵权问题查 [侵权品牌清单](../../../知识库/速卖通侵权品牌.md)。没有对应规则就登记缺口，并查目标平台官方来源；不能沿用Joom的标题限制、证书、广告机制或佣金。

### 历史事实与未关闭建议

在 `商品优化/`、`商品诊断/`、`调整记录/`、`执行记录/`、`复盘/` 及相关最新 `日报/` 中，用商品ID、建议编号、店铺和问题关键词检索。先列文件和命中行，再读相关报告及配对快照，不全量倾倒JSON、图片或历史快照。

确认是否已经修改、待审核、已生效或仍在观察；同一建议沿用稳定编号，不重复执行旧动作。历史记录中的用户确认可作为事实证据，但历史价格、库存、在售字段和状态须按本次需要复查。日报统计窗口不是抓取日；新保存的文档也不自动代表新业务状态。

## 形成有依据的优化动作

- 将平台要求、项目策略、用户已确认事实、当前观察及待核实项分开。官方建议不等于利润保证。
- 每项重要动作关联本地证据路径，以及相关官方来源编号（Joom为S编号）、核查日与适用范围。涉及会变更的规则、实时商品或投放状态时，核查最新来源；已有知识用于确定查什么，不能代替需要的实时验证。
- 优先修复实际问题：可售限制、信息冲突、实测尺码/真实供应、图案授权、价格运费和履约，再按曝光→点击→加购→成交定位机会。不要把所有问题都归结为标题或关键词。
- 不编造面料比例、尺寸、授权、发光效果、库存或利润。缺关键事实时，先完成可独立进行的诊断；需要时集中询问最少的缺失信息。不要为了清除提示填写虚假数据。
- 提出具体字段或设置的“当前值→建议值”、目的、依据、风险与复查条件。若用户已授权修改，沿授权范围完成并验证；未授权的预算、竞价、库存、地区、上下架等操作不得由文案优化推导授权。不要重复询问已获得的同范围授权。
- 保存、审核通过和真实在售生效分别核实。只有实际保存证据才能标记已执行；效果从真实生效日按项目分析方法观察。

## 归档与回答

沿知识库已有目录和命名约定保存本次诊断、执行证据或复盘；报告注明实际日期、范围和缺口。新的可靠平台规则补到对应规则文档及来源索引，用户新确认事实按范围更新经营规则，不覆盖旧快照或篡改历史结果。普通商品优化不必改写整套知识库。

答复先给本轮主要发现/结果，再给具体改动或建议，并链接本地报告和适用规则。让用户看得出“为什么这样优化、是否已经执行、还缺什么、何时复查”，无需复述整份规则。若未找到知识库，明确缺失位置；继续能做的工作，不假称已经查过。

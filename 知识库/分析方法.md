# 分析方法与归档约定

## 证据与日期

先核实报表日期、平台时区、更新时间和分页，再分析。上午实时数据只与此前同一时段比较；完整日对比前一完整日、同星期或此前 7 天日均。报表有延迟时，用最新完整日并明示日期。两个平台的自然日、访问和销售额定义可能不同，不直接合并。后台“利润”未核实采购、广告及售后口径前，不作为净利润。

每次运行读取本文件和经营规则，再读取相关最新快照及未关闭建议。历史数字保留其原始日期，不冒充新数据。Joom 广告可能存在点击后 14 天归因及回补，每次以当时规则为准。1—2 笔成交或少量访问不足以认定稳定效果。

## Joom官方规则依据

做Joom商品、广告或店铺优化前，先读 [Joom平台规则](平台规则/Joom/README.md)与 [优化检查清单](平台规则/Joom/优化检查清单.md)，按需查阅 [来源索引](平台规则/Joom/来源索引.json)和官方原文。每项具体建议引用规则S编号、核查日期与适用范围，并把平台要求、项目建议和待确认事实分开记录。2026-11-26完成首轮定向学习；相关动态规则超过30天、出现新公告/诊断或资料冲突时，行动前重新核实原文。30天是项目复核约定，不是平台时限。

重点核对标题/描述/属性一致性、真实材质比例与成衣尺码、印花和图片权利、目的国合规、广告策略单位及归因、逐变型定价和订单履约。官方店铺健康指标使用各自的考核周期与概率评估，不能把经营日报滚动56天退款率直接映射为官方质量问题退款率或店铺等级。编辑保存、审核和在售生效分别记录。

规则学习及检查清单不改变经营成本、定时任务或操作授权；当前授权仍按用户指示与经营规则核实。

## 盈亏计算

用户确认 Joom 普通单件衣服和无拉链卫衣约 ¥10，拉链卫衣约 ¥16，均含印花、包装、国内发仓。套装、多件和未知品类按实际数量与成本核算；美客多无可靠 SKU 对应时不套用该成本或 Joom 佣金。

正常成交保本 ACOS =（扣平台佣金和折扣后的卖家收入 − 完整采购成本折合美元 − 明确额外扣款）÷ 对应 POGS。

POGS 是广告售出商品原价总额，并非最终到账。总 ACOS 用总花费除以总 POGS，不平均各行百分比。销售额为零时 ACOS 用 null，不把页面的 0% 当优秀。历史金额有四舍五入，保留显示值。

不重复扣平台佣金、折扣、买家承担的国际物流；重量扣款与同一运费差额不重复计入。“付款佣金”按实际账单承担情况处理，不能看到字段就从所有正常订单扣除。退款按订单归属期及实际责任额匹配，不跨期直接扣历史汇总，也不重复冲减收入。正常成交贡献利润与最终净利润分开。

## 调整判断

建议初始管理目标 ACOS 约 20%，它是本次分析建议，不是已执行设置或保证不亏的门槛。

预算确实限制增长、成交样本足够、考虑售后后有利润空间且库存履约可支持，才建议加具体活动预算。预算花不完时，先检查竞价、流量和转化。竞价调整需区分 CPA 百分比、目标 ACOS 与 CPM 单价；通常小步试验，预算 10%—20%、竞价相对 5%—10%只是参考，不每天机械递增。

每项建议给当前值、建议值、金额或百分点、证据、预计改善环节、复查窗口和止损条件。没有单 SKU 预算功能时，建议商品竞价或拆分独立活动，不能虚构商品预算。转化差先检查主图、标题、属性、价格与运费、尺码、评价和时效。失效或政策受限商品先核实原因并修正或申诉。

## 调整与复盘记录

建议状态依次为：待确认、已确认执行、观察中、已复盘；不适用或用户拒绝的建议可关闭。没有用户确认或后台设置变化证据，不推进到已执行。每天跟踪同一建议编号，避免重复加预算。

每次在本任务自己的调整记录目录写独立 JSON 事件文件，不让两个同时运行的任务覆盖同一个总台账。事件应含建议编号、对象、时间、事件类型、执行前后值及证据、关联快照、复查条件；未知项为 null。复盘说明对比窗口、样本、促销和库存等混杂因素，相关性不写成因果。仅可将有证据支持的经验写入复盘；修改用户确认的成本或权限须有新的用户指示。

## 文件与验证

每日 Markdown 报告和 JSON 快照使用相同北京时间日期与时间作为文件名，报告链接配对快照。JSON 每个指标组记录 source、window_start、window_end、platform_timezone、captured_at、data_updated_at、currency 和 completeness；无法取到的字段为 null 并写原因。经营任务按平台、国家、店铺分别记录，不能将某国替代全平台。

每个文件先在同目录临时文件写完，再原子替换到新的、未使用的正式文件名。读回确认 JSON 可解析、金额加总及 ACOS 计算一致、Markdown 链接存在。不能写入时在聊天中明确失败路径和原因，不声称已保存，也不在别处创建未告知的第二份知识库。客户信息和凭据不得进入文件。


## 跟踪已提交的商品优化

每日经营监控读取“商品优化”和“调整记录/店铺经营”中的未关闭记录。先核实编辑版本是否通过审核、在售版本是否已更新，再按真实生效日建立优化后观察窗口；保存日不能自动视为生效日。观察 3 天曝光与点击、7 天转化、14 天归因及售后，样本不足继续观察。保留前后快照，说明价格、促销、库存和投放变化等混杂因素。这里只跟踪和建议，不自动再次修改商品。用户本次对低销量商品的修改授权不扩展为定时任务自动改商品或高销量商品的授权。
